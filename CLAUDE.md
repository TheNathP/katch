@AGENTS.md

## Product

**Katch** is a mobile color-hunting game, in the spirit of Cémantix but with colors: the app picks a random target color, the player photographs a real-world object that matches it as closely as possible, and gets a score based on how close the photo's color is to the target.

## Backend security model (core design decision)

The backend is the **only** layer that talks to the database. Assume the app can be decompiled and every request forged.

- The app uses `supabase-js` for **auth only** (session/JWT). All reads and writes go through **Supabase Edge Functions**, which validate input, check the user, and query the DB.
- Tables have RLS enabled with no policies granting `anon` / `authenticated` direct access.
- **Scoring is server-only.** The app uploads the **photo**; the server extracts the color, computes the score and stores it. The app never sends a color or a score, and never decides a game outcome.
- No shared `packages/`: the API contract is duplicated on purpose — the backend defines request/response types in `apps/backend/supabase/functions/_shared/types.ts`, the app mirrors them in `apps/mobile/src/data/api.types.ts`. When an endpoint's shape changes, update both in the same PR.

## Supabase

- The Supabase CLI is a devDependency of `@katch/backend` and must run from `apps/backend/` (it looks for `./supabase/`).
- The hosted project is `katch` (eu-central-1, Postgres 17). The link lives in `supabase/.temp/` (gitignored), so each developer runs once: `cd apps/backend && pnpm exec supabase login && pnpm exec supabase link` (asks for the DB password).

```bash
pnpm db:reset             # re-apply migrations + seed locally
pnpm functions:serve      # serve Edge Functions locally
cd apps/backend && pnpm exec supabase migration new <name>
cd apps/backend && pnpm exec supabase functions new <name>
```

## Notes

- `apps/mobile/expo-env.d.ts` (gitignored) is generated by `expo start`; typecheck fails on a fresh clone until the app has been started once.
- pnpm uses isolated installs (supported since SDK 54); only switch to `nodeLinker: hoisted` in `pnpm-workspace.yaml` if a native build breaks.
- Planned but not yet set up: Prettier, Jest (`jest-expo` + React Native Testing Library), GitHub Actions CI running lint + typecheck + tests on every PR. When they're added, document the commands (including how to run a single test).

## Stack (apps/mobile)

- Expo SDK 58, React Native 0.88, React 19.3, TypeScript strict, Expo Router with typed routes.
- **React Compiler** is enabled — don't add manual `useMemo`/`useCallback`/`React.memo` for perf unless measured.
- UI styling and client state libraries are **not decided yet** — ask before introducing NativeWind, Zustand, TanStack Query, etc.
- The app is still the `create-expo-app` template, not yet migrated to the target architecture: `src/app/_layout.tsx` renders `AppTabs` (`expo-router/native-tabs`), theme tokens are in `src/constants/theme.ts` (target: `src/styles/theme.ts`), `index` / `explore` are placeholders.

## Conventions

- Code, identifiers, comments, commits and ADRs in **English**; user-facing strings in **French**.
- Every technical choice (new library, architecture, workflow or tooling change) gets an ADR in `docs/adr/` (`NNN-title.md`, same structure as `001-react-native-expo.md`), included in the PR that introduces it. Propose one when a change introduces such a choice.
